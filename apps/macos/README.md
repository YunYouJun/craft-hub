# Native macOS prototype

This SwiftUI app prototypes the primary macOS host proposed in [ADR 0012](../../docs/adr/0012-make-a-macos-native-client-the-primary-desktop-host.md) (milestone M1 in the [native client goal](../../docs/plans/macos-native-client.md)). The window chrome is native: a system sidebar, toolbar and menus that adopt Liquid Glass on macOS 26 and later. Environment inspection, software browsing, the command palette and quick capture use native views; other content uses the existing web workbench in a `WKWebView`. Electron remains the shipped desktop host.

## Build and run

Requires Xcode 26 or later, the repository's pnpm dependencies, and a compatible Node (22 ≥22.18, 24 ≥24.11, or 26) on the machine.

```sh
./script/build_and_run.sh --verify
```

The Codex Run action uses the same script. It stops the previous native app, builds the bundle and opens it with Launch Services. Use `--logs` to stream native process logs, or `pnpm build:macos` to build without launching.

The build compiles the runtime and the web workbench, then bundles the runtime sidecar (`apps/desktop/src/sidecar.ts`) and the runtime CLI into single ESM files with `apps/macos/scripts/bundle-sidecar.ts`. The Microsoft To Do connector is bundled in place of its installed package. Only native addons (`node-pty`, `keytar`), `jsonc-parser`, the `cross-spawn` parser, the software catalog and the pinned Workstation runtime (built once and cached in `apps/macos/build/`) stay beside the bundles; Electron-only files never ship. The build starts the bundled sidecar once and fails if it does not hand back its bootstrap URL, then compiles this package in release mode and assembles an ad hoc signed app in `apps/macos/build/`. Run the Node resolution and native API contract tests with `swift test --package-path apps/macos`.

## Compatibility checks

`apps/desktop/test/fixtures/node-host-contract.json` is shared by Swift and TypeScript tests. It covers the published Node range and fixed GUI search order, including pnpm and fnm. Supporting a new Node major requires extending the bounded engines range and the CI matrix together. The native CI job builds/tests on `macos-26` and verifies the local app signature; the runtime compatibility job covers Node 22, 24 and 26. Hosted execution is still required to verify those jobs.

The [desktop bridge v1 inventory](../../docs/guide/desktop-bridge.md) records every method, its owner and current host support. Both hosts expose `bridgeVersion: 1`; unsupported methods remain absent so the browser and web fallbacks continue to work.

## How it works

- **Node:** the app ships no Node. At launch it resolves one executable: `CRAFT_HUB_NODE`, a path chosen in the app, or the first compatible Node found by the Electron host's fixed GUI search rules (`PATH`, `~/.local/bin`, Homebrew, `/usr/local/bin`, pnpm, fnm). It never runs shell startup scripts. With no compatible Node, a native view explains why and lets you choose one.
- **Runtime sidecar:** `apps/desktop/src/sidecar.ts` composes the same runtime as Electron through `createDesktopHostRuntime` in `apps/desktop/src/host-runtime.ts`: the Codex configuration, Microsoft To Do and Workstation host plugins, approved host extensions, and Codex agent tasks. It runs with a minimal environment (no `NODE_OPTIONS` or `NODE_PATH`), prints a one-use bootstrap URL, guards browser requests with a session cookie and native API requests with a separate bearer token, and exits when the app closes its stdin pipe, including after a crash or force quit.
- **Native pages:** environment inspection shows tool availability, versions, search paths and the active Node executable. Software browsing supports local search, detected/undetected/unknown filters, source failures and opening supported applications by catalog ID. “Configure Environment” and “Manage Software” open the full web workflows; the toolbar's “Back to List” returns to the native page. Observations are cached for the current session; Check Again refreshes them, and a runtime restart discards them.
- **Command palette:** ⌘K opens an independent panel with local page/project/command/skill search, category filters, `>` and `project:command` syntax, arrow navigation and Return selection. Search uses a small AppKit responder bridge so input-method composition owns its arrow and Return events. Project discovery is read-only and bounded to four concurrent projects. Selecting a capability opens its existing review UI; it never trusts a project or starts a run. Installed integration/workbench pages are searchable too.
- **Quick capture:** ⇧⌘Space opens a native panel, including while the main window is closed. The global shortcut uses Carbon and reports conflicts rather than replacing another registration; the app menu remains available. Reviewed fields, optional AI interpretation and Microsoft To Do creation use the existing runtime contracts. Web and native clients share `craft-hub/quick-capture` date/list parsing; `/api/work-assistant/capture-preview` is a same-origin, local-only, non-AI preview endpoint. Date/time review uses the system date picker.
- **Draft recovery:** native text, reviewed fields, preferred lists and the save request ID are stored atomically in `~/Library/Application Support/Craft Hub Prototype/native/capture-draft.json` (directory 0700, file 0600). The retry identity is durable before a remote create request. Timeouts preserve it, allowing the provider's existing idempotency journal to recover a prior success or reject an ambiguous pending write. Unreadable drafts remain untouched until the user chooses recovery, which keeps the original file. Connection replacement does not replace the draft store. Existing browser/Electron drafts and account grants are not migrated into the prototype.
- **Native API:** the first stdout line is `{ version: 1, url, nativeApiToken, pid }`. The token is generated per process, exists only in memory, and is valid only for `/api/` routes on that exact loopback Host/Origin. Swift uses an ephemeral URLSession with no cookies, cache or redirects. It never logs or persists the handshake. Native requests still pass through all runtime trust, discovery and provider checks. The web session cannot read the native credential, and native authentication cannot bootstrap a web session or call host routes.
- **Lifecycle:** a value-keyed `WindowGroup` keeps the app alive after its main window closes and lets panel actions reopen the same main scene. Recreated web views share one ephemeral website data store until the runtime connection changes, so reopening a window does not reuse the one-use bootstrap without its session cookie. Startup has a 30-second handshake timeout and a 16 KiB handshake limit. Every launch has an identity, so late callbacks from an old process cannot replace current state. Restart waits for the previous sidecar to exit (stdin close, then TERM/KILL deadlines). Unexpected exits after readiness retry at most twice per manual start; failures remain visible with Retry. The session and selected page are restored after recovery.
- **Bundled plugins:** plugin management can inspect and toggle optional plugins shipped with the app, including Microsoft To Do. The sidecar rejects arbitrary extension IDs; adding or changing external executable modules remains unavailable in this host. Restart checks for active commands, agent tasks and capture saves before replacing the runtime. To Do account consent remains separate from enabling its bundled connector.
- **Desktop bridge:** the app defines the same `window.craftHubDesktop` contract the web UI uses with Electron. Folder selection, external links and the clipboard run in Swift (`DesktopBridge.swift`) and answer only the workbench's own main frame; opening a saved workbench tool goes to the sidecar because it needs runtime settings.
- **Embedded web UI:** the app defines `window.__craftHubNativeHost` before the page loads. The web UI then hides its own titlebar, activity rail and status bar, accepts navigation, reviewed capability selection and settings commands from the native chrome, routes palette/capture requests back to native panels, and reports each route so the sidebar follows. One nonpersistent web view stays alive while native pages are visible, preserving web drafts during page switches; a runtime crash still recreates the web view. See `apps/web/src/native-host.ts`.

## Prototype limits

- Runtime state lives in `~/Library/Application Support/Craft Hub Prototype`, separate from the Electron app, so projects and settings start empty (ADR 0012 open question 4).
- Missing desktop bridge capabilities include editor, terminal and Codex launching, settings file, personal cloud, external host extension installation/removal, menu and deep link events, and theme and locale sync. Updates use native Sparkle menus and settings rather than the Electron bridge.
- Software installation, source management and environment configuration still use the full web workflows. Native observations refresh on demand; API event-stream refresh is not yet connected.
- Not yet implemented: menu bar item, App Intents, notifications, the login-shell PATH fallback and the private Node download. Native observations and palette discovery refresh on demand; event-stream updates, custom shortcut synchronization and pinned-result ranking remain follow-up work.
- Local builds are ad hoc signed and do not start an updater. Release builds use Developer ID signing, notarization and Sparkle 2; see [native distribution](../../docs/guide/native-macos-release.md). The [Alpha 6 → Alpha 7 acceptance record](../../docs/research/native-macos-update-acceptance.md) covers public installation, running-command cancellation, Later/Skip and app-scoped check-stage offline recovery, with remaining coverage stated explicitly.

## Software updates

The application menu provides **Check for Updates…** and **Software Update Settings…**. Sparkle owns the standard permission prompt, daily scheduling, background download, release UI, version comparison and installation. Users choose automatic checks and downloads; those preferences are never reset at launch. Local builds show an explanation in update settings and never request a feed.

Native releases keep their own bundle identity, data directory and architecture-specific feed, independent of Electron. The build pins Sparkle through SwiftPM and embeds its framework with symlinks preserved. Release archives and feeds use Ed25519 signatures; archives are verified before extraction. Normal quit and update restart both wait for the sidecar to drain. If work is running or its state cannot be confirmed, users can cancel the quit or explicitly interrupt it.
