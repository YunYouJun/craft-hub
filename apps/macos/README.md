## How it works

- **Identity maintenance entry:** `CraftHubMain` dispatches the fixed recipient mode before SwiftUI creates its delegate or normal profile lease. It authenticates the running source parent, bounds the private protocol, and uses the existing Keychain participant for staging and recovery. Source-owned authenticated launch, consent and recovery are implemented, but real Developer ID pair acceptance remains pending; release capability markers and real identity migration stay disabled. `pnpm test:macos-identity-recipient` verifies actual-app refusal from an untrusted parent without creating a profile; see the [receiver contract](../../docs/guide/native-secure-storage.md#native-maintenance-receiver).
- **Node:** the app ships no Node. At launch it resolves one executable: `CRAFT_HUB_NODE`, a path chosen in the app, or the first compatible Node found by the Electron host's fixed GUI search rules (`PATH`, `~/.local/bin`, Homebrew, `/usr/local/bin`, pnpm, fnm). A fixed probe checks version and actual CPU architecture within 3 seconds and 4 KiB; its process group is cleaned up even if TERM is ignored. Startup never runs shell startup scripts. When no compatible executable is found, **Read Login PATH** explicitly runs zsh/bash once with noninteractive login files, a 5-second timeout and bounded output. The discovered executable receives the same version/architecture checks before saving it as the selected path. A rejected explicit choice shows its reason and fallback; with no compatible Node, a native view lets you choose one. Set `CRAFT_HUB_TEST_NODE` to a real executable when running Swift tests to enable the opt-in probe test; native CI does this automatically.
- **Runtime sidecar:** `apps/desktop/src/sidecar.ts` composes the same runtime as Electron through `createDesktopHostRuntime` in `apps/desktop/src/host-runtime.ts`: the Codex configuration, Microsoft To Do and Workstation host plugins, approved host extensions, and Codex agent tasks. It runs with a minimal environment (no `NODE_OPTIONS` or `NODE_PATH`), prints a one-use bootstrap URL, guards browser requests with a session cookie and native API requests with a separate bearer token, and exits when the app closes its stdin pipe, including after a crash or force quit.
- **Native pages:** environment inspection shows tool availability, versions, search paths and the active Node executable. Environment profiles support native selection, revision-aware save/import/export, target review and prerequisite guidance; source connections have a separate native form and transient authentication. Software has catalog, favorites, installation history and repository-source tabs, with search, detection filters, application launch, reviewed installation, cancellation and source previews. Favorites share the personal workbench settings and support catalog addition, grouped search, opening and reviewed removal. Configuration review, application, history/restore, repository operations and Skills audit have native views. Registry editing and encrypted backup targets also have native review flows. Custom tool editing retains the web workflow; the toolbar's “Back to List” returns to the native page. Runtime events invalidate cached observations; visible pages refresh immediately, hidden pages when next opened. A change during loading requires a follow-up snapshot. Check Again remains available.
- **Live state:** one bearer-authenticated `/api/events` subscription survives main-window recreation. Redirects are rejected, frames are bounded, reconnect delay grows from 1 to 30 seconds, and cancellation closes the socket. Because the runtime offers no replay cursor, each connection refreshes snapshots. A generation guard rejects old-session callbacks and 150 ms batches merge bursts. Project catalog mutations now emit `project-catalog-change` for both web and native clients; discovery itself emits nothing. An open palette refreshes its index while preserving the query. Reconnection is visible and never grants trust or starts commands.
- **Command palette:** ⌘K (or the configured palette shortcut) opens an independent panel with local page/project/command/skill search, category filters, `>` and `project:command` syntax, arrow navigation and Return selection. Search uses a small AppKit responder bridge so input-method composition owns its arrow and Return events. Project discovery is read-only and bounded to four concurrent projects. Selecting a capability opens its existing review UI; it never trusts a project or starts a run. Installed integration/workbench pages are searchable too. Runtime-resolved capability pins rank ahead of equally relevant results and carry a visible and accessible pin marker; exact, prefix and name matches still outrank description matches. Pin updates publish the existing capability invalidation to other clients. An open native palette refreshes without resetting its query or selected item identity; a failed pin read keeps commands available and reports the missing state.
- **Quick capture:** ⇧⌘Space opens a native panel, including while the main window is closed. The global shortcut uses Carbon and reports conflicts rather than replacing another registration; the app menu remains available. Reviewed fields, optional AI interpretation and Microsoft To Do creation use the existing runtime contracts. Web and native clients share `craft-hub/quick-capture` date/list parsing; `/api/work-assistant/capture-preview` is a same-origin, local-only, non-AI preview endpoint. Date/time review uses the system date picker.
- **Draft recovery:** native text, reviewed fields, preferred lists and the save request ID are stored atomically in `~/Library/Application Support/Craft Hub Prototype/native/capture-draft.json` (directory 0700, file 0600). The retry identity is durable before a remote create request. Timeouts preserve it, allowing the provider's existing idempotency journal to recover a prior success or reject an ambiguous pending write. Unreadable drafts remain untouched until the user chooses recovery, which keeps the original file. Connection replacement does not replace the draft store. Existing browser/Electron drafts and account grants are not migrated into the prototype.
- **Native API:** the first stdout line is `{ version: 1, url, nativeApiToken, pid }`. The token is generated per process, exists only in memory, and is valid only for `/api/` routes on that exact loopback Host/Origin. Swift uses an ephemeral URLSession with no cookies, cache or redirects. It never logs or persists the handshake. Native requests still pass through all runtime trust, discovery and provider checks. The web session cannot read the native credential, and native authentication cannot bootstrap a web session or call `/__craft_hub_host/` routes. The narrow native-only `/api/native-host/extensions` endpoint reads component status and changes shipped optional components; a browser cookie cannot call it.
- **Lifecycle:** a value-keyed `WindowGroup` keeps the app alive after its main window closes and lets panel actions reopen the same main scene. Recreated web views share one ephemeral website data store until the runtime connection changes, so reopening a window does not reuse the one-use bootstrap without its session cookie. Startup has a 30-second handshake timeout and a 16 KiB handshake limit. Every launch has an identity, so late callbacks from an old process cannot replace current state. Restart waits for the previous sidecar to exit (stdin close, then TERM/KILL deadlines). Unexpected exits after readiness retry at most twice per manual start; failures remain visible with Retry. The session and selected page are restored after recovery.
- **Host components:** plugin management can inspect and toggle optional bundled plugins, including Microsoft To Do. External modules use a separate native file picker and explicit trust review, with registration, enable/disable and removal; code loads only after restart. Bundled identifiers remain reserved. Restart checks active commands, agent tasks and capture saves before replacing the runtime. To Do account consent remains separate from enabling its connector.
- **Desktop bridge:** the app defines the same `window.craftHubDesktop` contract the web UI uses with Electron. Folder selection, external links and the clipboard run in Swift (`DesktopBridge.swift`) and answer only the workbench's own main frame; opening a saved workbench tool goes to the sidecar because it needs runtime settings.
- **Custom shortcuts:** native menus read `workbench.shortcuts` from the shared runtime and refresh on public settings/catalog events. The palette binding is cached per profile for launch; configured project capabilities are rediscovered before appearing in the **Project Shortcuts** menu. Actions only open the existing review flow, including for untrusted projects. Disconnection, invalidation or removal clears capability bindings; duplicate chords are ignored and the palette takes precedence. Invalid notation receives no native binding. Configure shortcuts in the full settings UI; macOS system/menu shortcuts retain their normal precedence. The global Quick Capture binding remains ⇧⌘Space.
- **Embedded web UI:** the app defines `window.__craftHubNativeHost` before the page loads. The web UI then hides its own titlebar, activity rail and status bar, accepts navigation, reviewed capability selection and settings commands from the native chrome, routes palette/capture requests back to native panels, and reports each route so the sidebar follows. One nonpersistent web view stays alive while native pages are visible, preserving web drafts during page switches; a runtime crash still recreates the web view. See `apps/web/src/native-host.ts`.
