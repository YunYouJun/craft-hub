# Shared UI components

Form primitives follow [shadcn-vue](https://shadcn-vue.com/docs/components/field)'s source-owned component approach. Input, Textarea, Checkbox and Field were adapted from its `new-york-v4` registry; Select and Dialog compose Reka UI primitives. Registry source can be inspected with `pnpm dlx shadcn-vue@latest view @shadcn/input @shadcn/textarea @shadcn/checkbox @shadcn/field`.

The host's semantic CSS tokens map to YunLeFun's base CSS and Workspace / Admin profile, rather than Tailwind classes. Both come from the pinned `@yunlefun/ui` package (`@yunlefun/ui/css`, then `@yunlefun/ui/admin.css`); keep Craft Hub overrides in `src/styles/tokens.css` rather than copying upstream CSS. Desktop controls use 32px default and 28px compact heights; the profile increases them to 44px and 40px on narrow or coarse-pointer surfaces. Shared form styles live in `src/styles.css`; keep colors, focus, disabled and invalid states there rather than overriding them on individual pages. `theme.ts` synchronizes upstream theme classes with the existing theme preference, including portaled controls.

Button variants share the same size geometry, medium text weight and flat surface in pages and portals. Default icons are 16px and compact icons are 14px. Dialog panel footer actions use the shared size and a 72px minimum width for default text buttons; longer labels retain their natural width. Do not override Button's density or add an outer shadow in a page or footer.

For paired confirmation actions, wrap two default text buttons in `dialog-action-pair`. Its desktop columns are equal with a 112px minimum each; narrow and coarse-pointer layouts fill the footer with equal columns. Keep both labels text-only and use semantic variants for priority. Height, type and padding remain owned by Button; the pair owns only width and spacing. Avoid changing the columns when the action label changes after success.

Use `--danger`, `--warning` and `--success` for status text, and the separate `--danger-fill`, `--warning-fill`, `--success-fill` with their corresponding `--on-*` tokens for solid surfaces. Do not put on-fill text on a status-text background. Icons come from the existing icon module; brand icons are compiled from local Iconify collections with explicit safelists, and unknown brands retain semantic icons and visible names.

For detail dialogs with long content, use `DialogShell layout="panel"` with `title`, optional `description` and `header-actions`, default body, and `footer` slots. The shared panel keeps the header and footer visible while the body scrolls within the viewport. Its width, padding and title size use the dialog tokens in `styles/tokens.css`; colors, radius and overlay use the existing theme. Default DialogShell layouts are unchanged. Use FormSelect's `placeholder` for an unselected value rather than an empty option.

Compose `FieldGroup`, `Field`, `FieldLabel` and the control, associating labels with unique control IDs. Pass native attributes to Input and Textarea; use `v-model` for values. Use `data-invalid` on Field and `aria-invalid` on its control when validation reports an error. FormSelect forwards required and disabled state to Reka UI. Provider validation and confirmation remain the responsibility of the consuming form.

Configuration review composes Reka Tabs using the shared workbench tab geometry, and reuses DialogShell for prepared plans. Badge and Alert are small source-owned semantic wrappers for status and feedback; their variants use host theme tokens. Avoid adding page-specific control colors or new dialog implementations.

Navigation geometry belongs to `styles/tokens.css`. `NavigationList` and `NavigationItem` are presentation primitives with `as` / `asChild`; use them for route or action navigation while retaining the consumer's links, URL state and accessible roles. `variant="segmented"` is the default; `variant="sidebar"` provides source-list rows with a shared icon and label treatment. Items inherit their list's variant through groups, and explicit item variants take precedence. Use `ui-navigation-label` for text that can truncate and the `icon` slot for a decorative icon. With `asChild`, place the icon and label in the single child element. Disabled buttons use native disabled state; disabled links prevent activation and leave the keyboard tab sequence.

For panels in one view, use the shared `ui/tabs` exports. `TabsRoot` and `TabsContent` are Reka primitives; `TabsList` and `TabsTrigger` add navigation presentation while preserving Reka's focus, keyboard activation, orientation, selected state and disabled behavior. Set `TabsList variant="sidebar"` for settings navigation and `TabsRoot orientation="vertical"` for the corresponding keyboard behavior. Horizontal sidebar lists use the same rows without changing their semantics. Route navigation is not a tablist unless it actually controls associated tab panels.

Desktop segment triggers are 26px high inside 2px padding and a 1px border, making a 32px group. Sidebar rows are 32px; both use 13px type, a 20px line height and 16px icons. These are Craft Hub density choices, not dimensions mandated by macOS HIG. At widths up to 760px or with a coarse pointer, triggers and sidebar rows are at least 44px; a segmented group becomes 50px high. A narrow 900px desktop window with a fine pointer retains desktop density. Keep spacing outside the navigation list with the consuming layout rather than adding page-specific trigger height, colors or padding.
