# Craft Hub 日常工作台落地计划

日期：2026-10-12。状态：第一里程碑已实施并验证，来源适配与业务工作台按后续里程碑推进。

日常工作台将来源待办、已确认的本机项目和外部工具连起来，首先完成“待办 → 项目 → 打开工具”。业务数据与动作由插件提供，Craft Hub 主应用负责通用契约、界面、持久化和权限边界；实际编码、Agent 会话、终端与代码审阅继续交给 Orca 等外部工具，快捷动作由 Raycast 承担。

日常工作台作为可选插件工作台交付。本轮优先实现这条插件流程，主应用的软件与环境方向继续遵循 [ADR 0011](../adr/0011-focus-on-machine-setup-and-environment.md)，现有个人总览保留入口。工作项的权威仍在来源系统，项目关联与交接记录属于 Craft Hub 本机用户状态。

## 首版使用流程

1. 用户启用来源插件，连接账号并选择参与聚合的列表或资源范围。
2. 打开日常工作台，查看自己未完成的事项，以及各来源的账号、加载范围和更新时间。
3. 选择事项，确认其本机项目；首次确认后保存关联，下次复用。
4. 选择工具，补充本次目标，审阅事项来源、项目路径和必要上下文。
5. 复制交接文本并打开工具，在目标工具中继续处理；需要查看原事项时直接进入来源。

个人生活待办可以不关联项目，直接进入原事项或打开常用工具。未关联项目的研发事项显示“选择项目”，不静默采用当前项目。打开工具成功只代表启动请求成功，首版继续报告 `contextTransferred: false`；自动传递上下文与来源状态回写放在后续里程碑。

## 四个功能分组

分组名称、顺序与视图引用由组合插件的 `workbenches[].views[].group` 声明，复用现有分组侧栏。主应用不写入业务来源名称，也不把这四组设为所有用户的固定导航。

| 顺序 | 分组 | 首版内容 | 后续内容 |
| --- | --- | --- | --- |
| 1 | 工作事项 | 聚合待办、来源与账号筛选、未关联项目提示、原事项入口 | 截止日期视图、原生完成动作 |
| 2 | 项目研发 | 已关联项目、常用项目、命令与 Skills 入口、环境入口 | 项目与来源范围的关联建议 |
| 3 | 代码协作 | 已有插件的仓库、PR 和构建入口 | 待我审阅、失败构建摘要 |
| 4 | 设备调试 | 已有设备插件入口与连接状态 | 预览、Mock、日志与恢复操作 |

首版主要交付工作事项与项目研发的连接。其他两组组合已有视图；能力未安装时显示可用的接入说明，不生成示例业务数据。桌面使用分组侧栏，窄屏复用现有紧凑导航。

## 主应用和插件分工

| 交付层 | 负责内容 |
| --- | --- |
| `packages/craft-hub` | 通用工作项契约、精确来源引用、关联与交接状态持久化、校验、信任与执行边界 |
| `apps/web` | 通用待办聚合组件、来源状态、项目选择、交接预览和工具操作反馈 |
| `apps/desktop` | 受限原生工具打开与必要的 OS 桥接，保持薄宿主 |
| 组合 Marketplace Plugin | 四组视图引用、顺序、文案与可选快捷入口 |
| 各来源 Host Plugin | 官方 API、认证、分页、状态和身份映射、增量缓存及原生业务动作 |
| 各来源 Marketplace Plugin | 连接页、来源列表、动作与所需权限的声明 |

Microsoft To Do 使用独立适配插件，业务来源与设备适配留在各自插件中。组合插件引用现有来源视图，避免复制 Provider；私有业务配置和账号信息保存在对应插件或本机用户数据中。声明式插件不能执行 JavaScript 或独自承担 OAuth 与 API 调用，需要对应的受信任 Host Plugin。

复用已有 Host extensions 安装、信任审阅、启停和重启加载流程。插件依赖缺失、版本不兼容或来源不可用时显示诊断，健康来源仍然可用。

## 通用工作项和本机状态

第一里程碑兼容扩展 `IntegrationEntity`、`IntegrationEntityPage` 和现有 WorkItem adapter。新增字段均可选，旧来源无需伪造身份即可继续预览和手动交接；持久项目关联要求完整的 `sourceRef`。公开契约与浏览器安全 helper 见 `craft-hub/work-items`。

- **来源身份**：以 Provider 实例、账号、容器或资源范围、实体类型、原生事项 ID 构成 `sourceRef`。本机项目关联、缓存和交接记录统一使用该引用，不以标题或裸 ID 去重。
- **个人关联**：`personalMembership` 保存账号与 `owned`、`assigned` 或 `unknown` 关系，必须与来源及页面当前账号一致。Provider 负责归属事实；共享列表中的可见事项不能自动当作“我的”。
- **显示信息**：保留现有标题、说明、原生状态、优先级与来源链接，新增 `dueDate: { dateTime, timeZone }` 和 `updatedAt`。未知状态仍可见；当天与逾期的统一筛选留给第三里程碑。
- **来源进度**：`nextCursor` 保持不透明，`coverage` 表示已选查询的覆盖范围，`fetchedAt` 表示来源快照时间。账号切换不合并旧页，空页仍可继续，重复游标停止并提示；失败保留当前会话的最近成功结果并标记过期。持久来源缓存由后续插件负责。
- **项目关联**：支持事项级显式关联，以及用户确认的列表或资源范围默认项目。事项级关联优先，可明确选择不关联项目。多仓库候选、失效路径与已删除项目需重新选择。
- **交接记录**：后续保存来源引用、确认的项目 ID、工具 ID、时间和实际启动结果。第一里程碑提供共享交接草稿与真实启动反馈，尚不保存交接历史或创建 Agent 执行状态机。

来源适配首版每个 Provider 实例连接一个账号，账号过滤用于区分各来源身份；同时连接同一服务的多个账号后续再开放。当前个人列表过滤未完成事项并保留来源顺序；第三里程碑再提供截止日期、重要性和稳定来源键排序，没有日期的事项保持可见。

关联已保存在 OS Craft Hub 数据目录的 `work-item-projects.json`，版本为 1，仅保存来源引用与项目 ID；读取本机项目注册表解析实际目录，失效项目明确显示不可用。`GET/PATCH/DELETE /api/work-item-projects` 提供快照、更新与清除，陈旧修订返回 409。JSON 原子写入与 SQLite 事务侧车保障并发及中断恢复；损坏或未知版本保持原文件并报错。首次使用为空关联，此前手动草稿没有持久数据需要迁移。更换机器后重新绑定，不将这些本机文件、token 或信任状态写入共享配置。

主应用继续负责项目边界：选择、关联或打开项目不授予信任；执行固定命令仍要求信任，以 `command` 和 `args`、`shell: false` 运行。读取待办、准备交接和启动工具不触发项目命令或安装 hooks。

## Microsoft To Do 接入

接入同一 Microsoft 账号的 Graph 待办。桌面应用和 Craft Hub 插件读取同一云端数据；本地离线修改先由 To Do 同步，之后才能在聚合视图体现。首版不依赖桌面应用缓存格式。官方能力、权限与限制见 [Microsoft To Do 接入依据](../research/microsoft-todo-integration.md)。

首版规划如下：

1. 使用 Microsoft Graph `v1.0`，支持可用的个人账号与工作或学校账号，连接时显示账号类型及实际可用性。
2. 使用公共客户端 OAuth 登录，优先验证系统浏览器与 PKCE；不把 client secret 放进插件或模板。复用现有连接页，核实注册回调与现有本机回调路由能否匹配，凭据保存在 OS 安全存储中。
3. 首次请求委托 `Tasks.Read`，仅聚合用户选择的自有非共享列表，即 `isOwner: true` 且 `isShared: false`；账号切换后隔离列表选择、缓存和项目关联。共享列表和分配视图的“我的”语义单独验证后再开放。
4. 发现列表并逐列表分页读取任务。首版分页读取为必需能力，任务级 delta 为可选优化；先验证仅 `Tasks.Read` 可用，失败则退回普通读取。列表级 delta 当前官方仅列 `Tasks.ReadWrite`，只读首版不用。
5. 提供手动刷新、来源原始入口及最后更新时间。自动刷新在实现时选择有界间隔，尊重 Graph 节流和 `Retry-After`；关闭窗口或断网后不承诺实时同步。
6. 任务没有稳定可用的直接链接时，显示列表或 To Do 网页入口与任务标题，不拼接未经验证的原生 deep link。Microsoft `linkedResources.webUrl` 指向任务关联的外部资源，不能直接当作该 To Do 任务的详情地址。

Graph 分页与增量 URL 由 Provider 按官方端点校验并处理，对 UI 返回不透明 cursor。任务移动到其他列表时原生 ID 可能变化；旧关联显示来源失效并允许重新确认，首版不按标题自动迁移关联。

工作或学校账号需要适用许可及 Exchange Online 邮箱，且可能需要管理员批准权限；由世纪互联运营的中国区云不在当前 To Do API 支持范围。接入失败时明确区分管理员批准、服务不可用、授权过期和网络错误。现有聊天中的 Microsoft To Do connector 授权不视为 Craft Hub 已获得授权，Craft Hub 插件需要自己的应用注册与连接流程。

完成任务的写回属于后续能力：用户选择启用时再申请委托 `Tasks.ReadWrite`，声明 `work-items.transitions/update-status` 的 `remote-write`，沿用宿主确认机制。API 成功后重新读取来源状态；打开工具、复制文本或收到摘要均不自动标记完成。

## 分阶段交付

### 第一里程碑 补齐通用契约和关联

- [x] 确定 `sourceRef`、个人关联、截止时间、分页范围与兼容版本，保留旧 Provider 的原有行为。
- [x] 补充插件引用聚合待办和项目目录的声明式通用展示契约，避免业务名称进入主应用。
- [x] 新增本机项目关联的 schema、读写 API、修订检查及首次空状态；提供清除关联操作并保留未知版本数据。
- [x] 抽出事项预览、项目选择和交接组件，让个人总览与插件工作台复用。
- [x] 测试账号缺失、同 ID 跨来源和跨容器、未知状态、自有任务与共享任务、项目失效和并发修改。

验收：旧来源无需修改仍能预览；新的个人来源无需伪造经办人也能表达“我的”；两条相同标题或相同裸 ID 的事项保持独立关联；项目关联不会改变项目 trust。

验证记录：2026-10-12，公开边界、lint、根目录 TypeScript、Web Vue 类型检查和完整构建通过；176 个测试文件通过，1091 项测试通过、2 项跳过。自动化覆盖重启恢复、事项与容器优先级、显式不关联、409 冲突、身份与范围切换、迟到响应、失败快照、原生 ID 不同于展示 ID，以及真实写入子进程被终止后的锁释放。原生事项 ID 和完整来源引用也用于详情与原生状态动作，更新结果经过相同边界校验。

浏览器验收使用临时数据目录与两个确定性 Host Provider，跑通插件视图 → 读取下一页 → 保存项目关联 → 复制准确上下文 → 页面重载恢复关联 → 打开项目。1440×1000 与 390×844 均验证，手机无横向溢出；页面识别、非空内容、无框架错误覆盖、控制台与截图检查通过，项目始终为 `untrusted`。Browser plugin not available，使用工作区 bundled Playwright。真实来源登录、Microsoft To Do API 和原生工具接收属于后续里程碑。

同日完成界面设计修正：聚合事项和项目目录采用连续分组列表，交接弹层使用共享表单、单一复制主动作与折叠上下文；遵循现有 YunLeFun Workspace / Admin 基础。设计及验收记录见 [UI 约定](../design/ui-foundation-direction.md#日常工作流的界面约定)。Chromium / WebKit 与 320–1440px 明暗主题验证通过；完整验证更新为 177 个测试文件、1103 项通过、2 项跳过。来源适配和插件业务交付仍按后续里程碑推进。

### 第二里程碑 接入 Microsoft To Do 和已有业务来源

- [ ] 完成 To Do Host Plugin 与声明式视图，验证公共客户端登录、凭据保存、退出及重新连接。
- [ ] 验证插件 token 缓存的 OS 安全存储实现；现有设备私钥 vault 不作为已可复用的通用 OAuth vault。
- [ ] 完成自有列表选择、任务分页、只读状态映射、刷新与失败恢复。
- [ ] 将已有业务来源映射到通用契约，复用其官方 API、认证与原生视图。
- [ ] 验证一个真实个人 To Do 账号；工作或学校账号通过连接前置检查，并在有可用账号时独立验收。

验收：To Do 与一个已有业务来源同时返回真实事项；相同事项 ID 不混淆；超过一页的列表可继续读取；一个来源失败时另一个仍能使用；退出账号后该账号数据不再展示，凭据不会出现在 UI、日志或导出中。

认证前置：需要真实应用注册的 client ID、支持账号类型与回调配置。client ID 是公开应用标识；token 和 token 缓存是敏感数据。组织管理员审批可能阻塞该账号验收，不阻塞其他健康来源和通用流程的开发。

### 第三里程碑 交付四组工作台和优先流程

- [ ] 组合插件声明四组及其顺序，处理未安装来源和不兼容版本。
- [ ] 工作事项提供来源、账号、状态、关键词与未关联项目筛选；展示加载范围和最后更新时间。
- [ ] 为事项选择或确认默认项目，补目标、预览并复制交接文本，打开已配置工具。
- [ ] 保存关联与最小交接记录，重启后恢复；对浏览器模式、应用缺失与复制失败提供可用回退。
- [ ] 在桌面和普通浏览器验证主流程，并检查 1440px 与 390px 导航和详情布局。

验收：从两种真实来源各选一条待办，关联正确项目、核对交接文本并打开工具；重启后关联仍在；不需要项目的个人事项能直接进入来源；用户能区分已复制、已请求打开和失败。原事项状态始终保持来源事实。

### 第四里程碑 验证外部接收和业务闭环

- [ ] 选择一个有正式接收接口的工具，验证真实项目定位、上下文接收和失败行为，再开放自动传递。
- [ ] 支持结果摘要返回同一来源事项；任务执行过程继续由外部工具管理。
- [ ] 实施可选 To Do 完成动作和各业务来源的原生状态变更，处理重试与并发状态变化。
- [ ] 按实际使用需求补代码协作摘要和设备操作，不扩大为新的会话、终端或代码审阅客户端。

验收：只有经过目标工具可观察结果确认后才能报告上下文已接收；来源状态更新单独审阅，写失败不会显示完成。第四里程碑不作为前三个里程碑交付的前置条件。

## 实施顺序和完成标准

实施顺序为通用契约与关联 → 两个来源适配 → 组合工作台与手动交接 → 自动接收与可选回写。各里程碑单独形成可审阅的改动，社区主应用只接收通用能力，业务实现分别进入插件仓库。

每次 runtime 行为变更增加发现、信任与执行测试；来源适配覆盖身份、分页、错误和状态映射。发布前执行以下仓库检查，并记录真实来源和桌面或浏览器验收结果：

```bash
pnpm check:public-boundary
pnpm lint
pnpm typecheck
pnpm test --run
pnpm build
```

首版完成标准仍为前三个里程碑的真实来源流程通过。当前已交付通用基础；来源认证、业务插件适配、四组实际业务组合与交接历史继续按后续里程碑实施。浏览器验收仅在隔离数据目录链接临时测试插件，现有用户配置与未提交改动保留。
