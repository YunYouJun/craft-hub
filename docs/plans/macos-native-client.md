# macOS 原生客户端目标

日期：2026-10-22。状态：目标已提出；架构决定见 [ADR 0012](../adr/0012-make-a-macos-native-client-the-primary-desktop-host.md)，仍为 proposed。尚无原生代码，各平台发布的仍是 Electron。

## 目标

让 macOS 原生客户端成为维护者日常使用的主力宿主。打开 Craft Hub、找到项目、记下一件事、启动工具，这几件最常做的事要和系统自带应用一样顺手；运行时、项目信任与执行边界保持不变。

**切换完成**同时满足以下三条：

1. 维护者连续两周只用原生版作为日常宿主，没有因为缺少功能或体验问题退回 Electron。
2. 下文的交互验收全部通过，未通过项有书面豁免理由。
3. macOS 上默认安装和打开的是原生版，Electron 版只作备用。

## 交互验收

速度目标在维护者的 Apple 芯片 Mac 上测量 release 构建。下表数值是提议值；M0 先测出 Electron 版基线，M1 测出原生版首个数据后再修订。

| 场景 | 目标 | 测量方式 |
| --- | --- | --- |
| 冷启动到窗口可交互 | ≤ 1 s 出现可点击的原生侧栏，包含查找 Node 的时间；运行时未就绪时显示原生占位，不出现空白窗口 | `os_signpost` 加 Instruments |
| 应用已运行时按 ⌘K | ≤ 100 ms 出现命令面板首帧 | XCTest 性能测试 |
| 应用在后台时用全局快捷键打开快速记录 | ≤ 150 ms 出现面板，光标已在输入框 | signpost 加手动复核 |
| 在命令面板里输入 | 每次按键在同一帧内更新本地结果；远端结果不阻塞输入 | Instruments 帧时间 |
| 侧栏切换页面 | ≤ 100 ms 出现目标页结构，数据随后填充 | signpost |
| 拖动改变窗口大小 | 内容不滞后、不露白边 | 录屏逐帧检查 |

### 系统行为一致

- [ ] **窗口：** 记住位置和大小，支持全屏和多显示器；关闭最后一个窗口时按 macOS 惯例保留应用和菜单栏入口。
- [ ] **键盘：** 主流程能只用键盘完成；侧栏可用方向键移动；有标准菜单项和快捷键（⌘, 打开设置、⌘W、⌘F 等）；Esc 关闭面板和弹层。
- [ ] **菜单：** 应用菜单、右键菜单和 Dock 菜单都是原生菜单。
- [ ] **文字输入：** 中文输入法的候选框位置正确，支持撤销、重做和拼写检查。
- [ ] **拖放：** 把文件夹拖到侧栏或 Dock 图标上即添加项目，新项目仍为 `untrusted`。
- [ ] **外观：** 跟随系统的深浅色和强调色；遵守“减少透明度”“减少动态效果”“增强对比度”。
- [ ] **无障碍：** VoiceOver 能读出全部控件，焦点顺序与视觉顺序一致。

### 系统入口

- [ ] **菜单栏：** 常驻入口显示今日重点、快速记录和最近项目。
- [ ] **全局快速记录：** 不用切换到主窗口就能记录。
- [ ] **App Intents：** 提供“打开项目”和“快速记录”，可在快捷指令和 Spotlight 中使用。
- [ ] **通知：** 带操作按钮，但只能打开对应页面，不能授予信任或运行命令。
- [ ] **深链接：** `craft-hub:` 继续只做导航，见 [ADR 0007](../adr/0007-keep-desktop-links-navigation-only.md)。

### 可靠性与安全

- [ ] 运行时辅助进程崩溃后自动重启，界面显示状态，未保存的快速记录不丢失。
- [ ] 正常退出和强制退出后都不残留 Node 进程。
- [ ] 优先使用本机已有的兼容 Node；诊断中心显示当前使用的 Node 路径和版本。用户升级或删除 Node 后，下次启动自动重新选择并提示。
- [ ] 固定规则找不到兼容 Node 时，引导页提供“从登录 shell 读取 PATH”按钮，照顾只靠 shell 启动文件配置的 nvm、Volta、asdf、mise。只有用户点击才会运行，启动时从不自动运行。运行一次登录 shell，非交互并设超时，只读取 `PATH`。找到的 Node 同样做兼容检查，并保存为用户指定路径，之后不再运行 shell。按钮旁说明这会执行用户的 shell 启动文件。
- [ ] 没有兼容 Node 时，原生引导页仍能打开并说明原因，满足 [ADR 0011](../adr/0011-focus-on-machine-setup-and-environment.md)。用户确认后才下载 Craft Hub 私有 Node 并校验官方 checksum；不修改用户自己的 Node 或 `PATH`。
- [ ] 原生端不执行项目命令。新项目仍为 `untrusted`，执行仍走运行时的显式信任和 `shell: false`；快捷指令、通知和菜单栏入口都不能绕过应用内确认。

## 准备工作（M0）

开始写 Swift 之前先完成这些。M0 期间 Electron 版照常发布。

- [ ] ADR 0012 从 proposed 改为 accepted。
- [ ] 决定最低 macOS 版本（ADR 0012 待定问题 1）。
- [ ] 决定数据连续性和应用身份（待定问题 4、5）。这两项会阻塞 M1：两个宿主不能同时操作同一份运行时数据。
- [ ] 把 Electron 主进程里的 Node 服务拆成共享的宿主后端，Electron 改用它启动且行为不变。
- [ ] 定好非浏览器客户端的鉴权合同。
- [ ] 把 `window.craftHubDesktop` 的 47 个成员整理成按用途分组、带版本号的桥接合同。
- [ ] 在运行时包里声明支持的 Node 版本范围，并在每个支持的大版本上跑测试。
- [ ] 把 Node 查找规则写成共享测试样例，现有的 `guiToolDirectories` 和后续的 Swift 实现都要通过。
- [ ] 决定 Node 选择细节（ADR 0012 待定问题 2）：优先用默认版本还是最新的兼容版本，是否支持 Volta、asdf、mise 的 shim，私有 Node 从哪里下载、如何升级；“从登录 shell 读取 PATH”支持哪些 shell、超时多长。
- [ ] 测出 Electron 版的交互基线：冷启动、⌘K、页面切换、拖动改窗口大小。
- [ ] 确定原生工程的位置（建议 `apps/macos`）、Swift 格式检查和 macOS CI runner。
- [ ] ADR 接受后更新 AGENTS.md 的架构说明。

| 里程碑 | 对应 ADR 阶段 | 完成标志 | 目标日期 |
| --- | --- | --- | --- |
| M0 准备 | 阶段 0 | 上一节全部勾选，Electron 跑在共享宿主后端上 | 待定 |
| M1 原生外壳 | 阶段 1 | 原生侧栏、工具栏和菜单加 WKWebView 内容区，维护者日用一周；首批速度数据入表 | 待定 |
| M2 高频入口 | 阶段 2 | 命令面板、快速记录、今日重点、项目列表和菜单栏入口原生化；达成“切换完成” | 待定 |
| M3 对齐与分发 | 阶段 3 | 签名、公证、自动更新、密钥迁移完成；停止发布 macOS 的 Electron 版 | 待定 |

**退出条件：** M1 结束时，以下任一项无法在一个迭代内解决，就暂停原生路线，回到“Electron 加 CSS”的改进方向，并在 ADR 0012 记录原因：

- 冷启动明显慢于 Electron 基线。
- 运行时辅助进程无法稳定退出，或在支持的 Node 版本上表现不一致。
- 原生外壳和网页内容之间的接缝严重影响日用。

## 不在本目标内

- Windows、Linux 的原生化；这两个平台继续用 Electron。
- 用 Swift 重写运行时。
- 新业务功能。原生版先追平现有功能再扩展。
- 让快捷指令、通知或菜单栏直接执行项目命令或授予信任。
