# 原生项目详情与插件渲染

项目详情由宿主提供。项目、包和能力发现由共享运行时处理，内置发现器和插件都可以贡献结构化结果；项目详情并不是由每个插件各自提供一份页面。

当前原生入口：项目列表、最近项目或命令面板选择项目后，显示 SwiftUI 项目详情，不创建 WKWebView。详情读取公共 `/api/projects` 和 `/api/projects/:id/capability-discovery`，展示项目名称、路径、当前信任状态、根包说明、命令、技能、来源与发现提示。支持名称/说明/来源搜索、能力类型及包筛选。未知能力类型保留可见，并提供完整项目入口。

项目详情的浏览仍只读，不会授予项目信任，也不启动命令、代理任务或插件写操作。普通命令的“查看与审阅…”打开原生参数表单、执行审阅与终端；技能、发布计划和“完整项目…”继续使用已有 Web 流程。README 完整排版、项目配置及复杂交接保留完整项目入口。网页工具栏的“返回原生项目”回到此前选中的原生项目，保留该页筛选；网页内部另选项目不会自动更改这个原生选择。项目列表按钮退出当前详情。

窗口关闭再打开保留当前运行时的原生详情。资料重连或运行时更换会清除旧观察并重新读取；项目、插件和配置事件使结果失效。刷新失败保留旧数据并明确标记过期，能力审阅入口等待重新读取。旧项目或旧运行时的迟到结果不能覆盖新选择。不会为这个页面增加后台轮询。

首次读取与缓存刷新采用不同的[原生加载反馈](./native-loading.md)：首次超过 200 ms 显示静态骨架，刷新保留真实内容与筛选，失败显示错误并提供重新读取。

## 原生命令审阅与终端

普通命令读取共享参数定义，原生展示文本、隐藏输入、选项、布尔值与条件字段。点击“审阅并运行…”后，由运行时解析输入并生成五分钟有效的一次性审阅，展示程序、逐项参数、工作目录、所需环境变量和前置步骤。未信任项目的确认明确包含保存项目信任；取消不会授予信任或启动命令。确认运行前重新核对项目路径、完整命令声明和输入，并在启动进程前再次检查。修改参数、声明失效或重复使用审阅需要重新审阅。执行仍使用共享 `command` / `args` 与项目工作目录，不拼接新的 shell 命令。发布命令保留完整 Web 发布计划与预检入口。

参数编辑通过只读预览接口重新解析，立即隐藏旧参数，迟到结果不能覆盖新输入。审阅由运行时保留完整声明和输入，绑定调用方身份；`trust` 和 `run` 携带审阅 ID，后者在等待发现前消费该 ID，并核对提交的能力与输入，再复用既有启动边界校验。旧客户端的执行接口保持兼容。原生流的启动确认期限为 30 秒；收到有效启动记录后，长时间没有输出不会按普通短请求超时。

内嵌终端采用固定版本 [SwiftTerm 1.19.0](https://github.com/migueldeicaza/SwiftTerm/releases/tag/v1.19.0) 的 AppKit `TerminalView`，由 `NSViewRepresentable` 接入 SwiftUI；没有使用自行启动进程的 `LocalProcessTerminalView`。轻量自写解析器已移除，PTY、信任、审阅、启动与停止继续由共享运行时管理。SwiftTerm 资源包和 MIT 许可随 App 打包。键盘、组合输入、选择复制、鼠标、备用屏幕及终端协议由组件处理；输入按原始字节排队，经兼容的 Base64 请求原样传给同一 PTY，窗口变化继续报告字符尺寸。

终端会话由 App 模型持有，页面隐藏时仍逐块处理实时控制序列，返回页面复用原模拟器。日志缓存裁剪不重建当前终端；首次非空实时输出中的查询正常回复，历史和替换快照不重发查询回复。断开连接会清除旧模拟器和输入回调，输入及尺寸回调绑定原连接和运行记录。完成或暂停输入不会篡改进程声明的光标显示状态。显示滚动历史限制为 2,000 行。终端输出不能自行修改系统剪贴板、App 标题/窗口、项目目录或触发文件传输；APC（含 Kitty 图片协议）在进入组件前按流过滤，避免组件直接读取或删除本地文件/共享内存。HTTPS 链接只在用户 Command 点击时交给系统打开。真实输入法、辅助功能及完整兼容性仍按各批次证据验收，不能由社区组件的功能声明推定通过。

运行记录按开始时间倒序展示。当前连接的实时输出按接收顺序追加；历史文件分别保存 stdout 和 stderr，重新读取时按这两部分展示，不能恢复原有交错顺序或完整终端初始状态，截断记录会显示提示。切换页面不会隐式停止命令。连接中断不会自动重跑或重接实时输出流；已知运行 ID 可从运行记录重新核对，后续输出需手动重新读取。没有收到启动确认时无法仅靠相似记录确定本次是否执行，需明确核对再继续。输入送达结果不确定时取消后续排队内容，检查输出并明确确认后才恢复输入。

## 独立终端入口

原生项目页和命令页都提供“独立终端”选择及“在独立终端打开…”入口。应用列表复用共享检测，支持已安装的 Terminal、Ghostty、iTerm2 与 Warp；选择保存在当前原生资料目录的偏好中，两页共用。保存的应用不可用时明确显示原因，须重新检测或选择其他应用，不自动换用另一终端。窄窗口将控件换行，读取和打开期间显示进度，旧连接或旧页面的回执不能覆盖当前提示。

项目页打开项目根目录，命令页打开当前命令声明的工作目录。原生请求只提交项目、命令和终端应用 ID；宿主重新发现命令，验证真实目录仍属于该项目，再复用 `shell:false` 的系统应用打开器。接口要求独立原生 bearer，网页 Cookie 不能调用，也不接受客户端路径、命令、URL 或运行 ID。未信任项目也可打开目录，操作不会授予信任或执行能力。外部应用创建自己的终端会话，不能接管应用内正在运行的 PTY。

## 插件怎样同时支持原生和 Web

同一份声明和结构化结果可交给多个宿主渲染。例如命令或技能的名称、说明、来源、包信息可以展示为 SwiftUI 列表，也可以展示为 Vue 列表。插件保持一份声明和业务实现，宿主各自维护渲染适配。

现有集成工作台已经这样处理连接状态、实体列表/搜索、通用表单、资源浏览和部分配置开关。是否自动读取仍取决于声明的 effect、confirmation 和作用域；支持原生展示不扩大插件权限。项目级配置管理和其他未覆盖业务块保留明确的完整页面入口。

| 内容 | 当前方向 |
| --- | --- |
| 项目概览、能力列表、搜索和状态 | 原生渲染共享结构化结果 |
| 普通命令参数、信任审阅、执行及基本终端 | 原生渲染，复用共享运行时与 PTY |
| 插件声明的标准列表、表单和审阅 | 逐步补齐宿主原生渲染，复用现有运行时验证 |
| README 完整排版、发布计划、复杂任务/交接流程 | 保留现有 Web 流程，按实际使用频率决定后续原生化 |
| 依赖 HTML/JS 的复杂交互 | 适合 Web 实现；当前变更不新增任意插件网页或可执行界面的加载能力 |

选择依据是内容和交互合同。插件贡献结构化数据时可以原生渲染；已有 Vue/DOM 实现不能直接交给 SwiftUI。原生化也不要求把 TypeScript 业务实现重写为 Swift。
