# Native resource collections and browser imports

Trusted resource adapters may return an optional `collection` on a `ResourcePage`. The shared contract in `packages/craft-hub/src/resource-pages.ts` contains inert columns, stable row IDs, display cells, copy values and navigation inputs. The shared Vue renderer presents collections in browsers and the native client's embedded workbench. Business validation, filtering, ordering, persistence and write confirmation remain in the runtime adapter.

The macOS host opens the workbench overview, contributed workbench groups and every integration view in the shared Web renderer. Sidebar entries, diagnostic links, configuration links and scoped integration URLs use the same route. This includes older declarations without a `rendering` hint; `rendering: 'web'` remains valid for other hosts that understand the hint. Project scope stays in the URL and unavailable projects are rejected before navigation. The duplicate SwiftUI integration list, resource browser, forms and connection sheets are removed after Release acceptance. Native home quick actions and host management pages remain independent consumers of the public runtime contracts.

The Web pages reuse the shared Button, Input, FormSelect, Checkbox, DialogShell, table, navigation and ActionToast modules. Reka UI owns keyboard, focus, selection and accessible transient feedback; host tokens supply the macOS appearance and light/dark themes. Ordinary browsers retain the same pages with native capabilities absent.

Confirmed integration requests report only a pending boolean through an origin-checked native bridge. Concurrent requests keep navigation, refresh, host restart and ordinary app termination protected until every request settles. Browser route changes use the same pending state. Background progress reads continue while foreground resource controls are disabled. No provider input or credentials enter this report. Resource exports use a bounded text/file-name bridge and a system save panel; the caller cannot select a filesystem path. Browser and Electron clients keep their existing download path.

Collections name the resource filter form and selection input. Filtering and selection invoke only the declared resource read action; batch writes still cross the existing one-use form prepare/execute protocol. Hidden form/document IDs suppress duplicate legacy presentation in capable hosts. Keep entity/document/form fallbacks so older clients remain usable.

Optional `copyDocumentIds` promotes provider-formatted documents to one-click copy buttons above the table. Empty content and pending filter or selection reads disable these buttons. Supporting hosts hide their document cards automatically; leave these IDs out of `hiddenDocumentIds` so older hosts retain the document fallback. Copy actions use transient, accessible toast feedback; secret values never enter its message.

An optional `browserImport` describes an HTTPS account page, a small exact-origin login allowlist, a same-origin POST request and a bounded JSON projection. It cannot supply JavaScript. The native host executes its own bundled request script in a separate `WKWebView` without any desktop bridge. A dedicated persistent website data store is scoped to the native profile and account-page identity. User interface actions open the page, refresh a preview and explicitly import the batch.

The host rejects unexpected navigation, an account change during a request, malformed declarations, duplicate credential identities and oversized batches. Closing the window invalidates in-flight results. A preview cannot be adopted after the page navigates. Import metadata uses the same reviewed resource form protocol; credentials are separated before any runtime request or form plan is created.

Passwords are stored only in `ResourceCredentialVault`, using the macOS Keychain and a service scoped by profile, integration, source ID and origin. Ordinary resource responses contain only opaque references. Listing uses metadata-only lookups, without reading secret bytes or prompting for Keychain access. Only explicit show/copy actions read credentials. Displayed values are cleared after 30 seconds, on disappearance and when the app becomes inactive; copy marks the pasteboard as concealed. There is no plaintext storage fallback or password export API.

The regular browser renderer presents the collection and management actions. It directs source login and local credential actions to the native desktop client and cannot access native passwords. The embedded native workbench uses an origin-checked, main-frame-only bridge with short-lived sessions. Native code resolves the installed declaration and row credential identity, then revalidates them before every credential action. An explicit show action may return a password to that embedded view; copying stays native. Passwords never cross the runtime HTTP API. Navigation, session replacement and app deactivation conceal displayed values, and account import retains its separate native window.

Returning from a native page emits a resource-resume event so the retained Web collection acquires a fresh credential session while preserving its filters and selection.

`scripts/native-resource-import.test.ts` executes the exact bundled request body with controlled browser dependencies, covering normal operators, control characters, request scope, authentication failure and identity changes. `ResourceBrowserImportTests` covers declaration validation, secret-free metadata, batch limits, real isolated Keychain access, profile/source isolation and removal. `ResourceDesktopBridgeTests` covers session and declaration revalidation, forged row identities, app inactivity and explicit import. Web component tests cover stale secret replies, concealment, copy feedback and disabled pending reads.
