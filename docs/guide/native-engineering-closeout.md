## XCTest 关键流程验收

独立夹具和运行器位于 `apps/macos/build/closeout-ui-20261024/`。它使用标准 `CraftHubMac` 入口、独立应用身份和 HOME/profile；27 个产品 `__TEXT` 节、App Intents 元数据及包内运行时与上述新候选一致。HTTPS 测试目录只服务本地声明式归档，证书信任只提供给测试子进程，不改变系统信任库。

成功结果为 `Result-20261024-171431.xcresult`，`report-20261024-171431.json` 保存 13 个检查点及清理结果，`summary-171431.json` 记录 1 项通过、0 失败、0 跳过。`screenshots/` 中七张窗口截图已经核对。实际完成：

1. 安装审阅分别用 Escape 和“取消”关闭；运行时没有下载或安装。
2. 审阅期间依赖升级并新增权限，首次确认须显示新计划，重新确认前不下载；二次确认后安装准确版本。
3. 移除审阅分别用 Escape 和系统“Cancel”按钮关闭，已安装版本不变；确认后目标插件消失、依赖仍为 1.1.0。弹窗显示保留用户数据及本地源文件的说明。
4. 损坏本地声明后，诊断详情显示插件名称、完整 JSON 错误、文件位置及检查时间；Escape 关闭，再打开并点击“管理插件”进入准确的本地插件详情。截图同时确认中文 README、`commands` 权限、包名/来源/版本；恢复声明后显示零错误、零警告及已完成检查无问题。
5. 每个检查点保持零项目、零运行记录，不执行插件声明的命令。

首次运行 `Result-20261024-141505.xcresult` 在用例开始前失败：系统要求本机身份验证，随后 XCTest 报告 `Timed out while enabling automation mode`。维护者确认方便处理系统验证后重新启动，自动化已获放行。之后修正四处测试脚本假设：等待 sidecar 握手就绪、仅在当前 sheet 查找按钮、按实际系统取消控件定位、使用诊断显示名而非包名选行。所有失败结果保留，没有放宽产品检查或修改产品代码。

运行器编译过程中修正了 Swift 6 的主线程声明。旧测试包最初缺少 `license`，添加 `UNLICENSED` 后又因 `private: true` 不满足 Marketplace 校验而失败；最终移除此字段，四份本地夹具均通过 CLI 校验，保留所有失败日志。包名和权限声明未变，没有发布这些归档。
