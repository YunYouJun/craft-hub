# 原生插件管理与诊断中心

macOS 候选版的侧栏使用 SwiftUI 显示插件管理和诊断中心，两页消费共享运行时 API。插件版本、权限、依赖、来源策略和项目执行权限仍由 TypeScript 运行时决定。

## 插件管理

- **发现**：搜索目录、筛选已安装或可更新插件，查看版本、权限、依赖和 README。安装前显示完整计划，计划变化后必须重新确认。
- **已安装**：启停、回滚、保留数据的移除，以及本地声明式插件目录的链接、重新读取和取消链接。取消链接保留源文件。
- **来源**：预览目录及发布者信息后添加来源，查看来源错误，刷新或移除自定义来源。来源导入链接只填写草稿。
- **宿主组件**：查看随 App 分发的组件，切换可选组件并在明确操作后重启运行时。外部代码扩展可选择本地 `distribution.json`、审阅后登记、启停及移除登记；所有操作均使用原生界面。

发现、已安装和插件详情显示声明中的专属图标。相对路径通过当前插件来源、包名和版本读取，
内联图像和 HTTPS 图像沿用同一展示组件；缺失、无效或读取失败时显示默认图标。
刷新目录或重新读取本地插件也会刷新同版本资源。外部图像请求不携带本机运行时凭据。

“检查更新”立即打开原生弹窗，分别显示检查中、无更新、检查失败、需要重新检查和应用结果。检查失败后清空上次的候选列表；插件或来源变化后，应用按钮停用，重新检查才能继续。一次应用会消费该检查结果，失败后的重试也需要重新检查。权限或依赖边界变化的插件仍逐个审阅。

网页内的 `/marketplace/plugins/:sourceId/:packageName` 详情入口会转到原生详情，保留来源和带 scope 的包名。后台网页迟到的路由不会抢走当前原生页面。诊断的插件入口复用同一详情流程。

发现与已安装列表支持系统行选择、双击打开详情和右键复制包名，也可使用底部的“查看详情”按钮。搜索会去掉首尾空白，在插件和来源分区保持一致；筛选或刷新移除已选项时清除选择。首次加载显示进度，空列表区分未安装、无匹配和读取失败，并提供清除筛选、查看来源或重试。刷新失败保留已有目录并提示结果已过期。

插件移除、回滚和来源移除的确认绑定当前运行时连接与目录。断开重连、相关目录事件、重新读取、切换分区或离开插件页都会清除未提交的确认；迟到的旧按钮不能操作新连接或覆盖新确认。点击确认同步消费本次审阅，再提交操作；回执失败时把目录标记为过期，须重新读取当前状态并再次审阅。移除仍保留用户数据及本地源文件。

### 外部宿主扩展

“添加外部扩展”打开系统 JSON 文件选择器。预览只读取声明并解析模块位置，不导入模块、不写入登记；原生弹窗显示扩展名称、ID、声明路径、模块的真实路径，以及同 ID 的已有登记。点击“信任并添加”才保存，下次重启运行时加载。此信任针对本地模块位置，允许这些位置的后续代码修改；它不是不可变代码摘要、沙箱或项目执行授权。

审阅结果有效期五分钟，最多同时保留八份，每次确认只消费一次。声明、解析出的模块位置或已有登记变化时拒绝保存；失败或结果未知后须重新读取并审阅。取消弹窗或离开页面使审阅失效，重连后的迟到响应不能恢复弹窗。启停与移除携带完整已显示登记，在运行时串行写入时比较，避免覆盖已被替换的扩展。移除只删登记，保留源文件及用户数据；当前已加载的代码仍需重启才停止生效。

随 App 提供的必需组件不能通过外部扩展入口覆盖；可选内置组件仍使用原有开关。外部登记接口只接受原生独立 bearer，网页 cookie 和内嵌网页桥接不能登记代码。项目继续默认 `untrusted`，扩展登记不会授予项目信任。

## 原生待办快捷操作

首页使用连续的系统内容背景。今日重点可收起并独立滚动；来源使用系统 Picker，
列表筛选与任务内容使用原生 List，选中态随窗口焦点和系统外观变化。
窄窗口将列表筛选收为顶部菜单，较窄的任务栏把快捷操作移到第二行；
分类与列表仍可组合筛选，来源图标、详情、状态确认和复制入口保持可用。

首页的今日重点、待办列表和插件工作台的工作项支持直接打开详情，并通过来源提供的状态候选修改状态。
来源图标沿用插件声明，界面不根据名称猜测业务图标。描述以可选择的纯文本显示，不执行 HTML 或读取其中的远端资源。

状态修改先展示事项名称、当前状态、目标状态和来源要求的必填字段；点击确认才提交一次。
确认前会重新检查插件操作、账号、事项状态和可用流转，过期或已变化时要求重新读取。
缓存快照只展示已载入信息，不能借助快捷操作写入。提交未得到明确回执时保留结果不确定提示，不自动重试；
确认后刷新来源并保留待办筛选。运行时重启和正常退出同样检查尚未结束的事项写入。

这些操作复用通用 Integration 契约。未声明读取或状态能力的来源不会由原生客户端补造操作；
来源自身仍负责权限、工作流条件和写入前的状态核验，客户端的重新读取不等于原子并发控制。

2026-10-27 的 Release 实机验收使用独立 profile 和仅写本地状态的测试来源，已确认完整详情、
取消后零写入、明确确认后单次写入和列表刷新；普通同步心跳保留确认页及搜索条件。
插件列表与详情的专属图标、缺失图标和损坏资源的默认图标均已截图核对。
真实账号来源另行验证了详情、工作流候选和必填字段阻止空值提交，未修改真实事项状态。
验收实例及其 sidecar 已关闭，日用原生版保持运行。

## 诊断中心

诊断页显示当前 Node 的路径和版本、错误/警告统计、来源状态、文件位置及处理入口。文本搜索、级别和来源筛选可以组合使用；“清除筛选”恢复全部结果。来源被移除后自动恢复全部来源筛选。

刷新失败时保留上次结果并标记过期。未完成、空、跳过或失败的来源不能被显示为全部检查通过。打开项目诊断只进入项目查看或审阅流程，不改变信任状态，也不执行命令。

诊断列表支持行选择和双击详情。原生详情弹窗提供完整消息、文件行列、诊断代码、来源说明和检查时间，可复制单条诊断，或打开对应处理页面。复制内容保留过期结果提示。刷新后详情读取同一 ID 的新结果；问题消失或运行时断开时关闭详情，筛选隐藏的问题不再保持列表选择。来源的失败说明也显示在来源折叠区中。
