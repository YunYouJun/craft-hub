# 项目与子包概览面板

## 状态

首次交付已实现。阶段一和阶段二已完成；后续环境状态、动态服务状态与统一安全快速运行继续保留在路线中。本文档不授权执行命令，也不改变现有的信任边界。

## 背景

当前选择项目时，Craft Hub 会加载已发现的能力、清空选中的能力和运行记录，并让右侧详情面板停留在空状态提示。子包选择仅存在于能力列表的局部状态中：它可以过滤中栏命令，却没有进入工作台 store，因此右侧详情面板无法感知或展示子包上下文。

这种交互可以满足“先找命令”的导航方式，但用户在选择命令前很难理解项目。对于 monorepo，问题尤其明显：应用、基础库、文档站和内部包都被压平到很长的命令列表里，尽管 Craft Hub 已经发现了它们的子包元数据。

右侧详情面板应当成为具有上下文的首页：

1. 选择项目时打开项目概览。
2. 选择子包时打开子包概览，同时限定能力列表范围。
3. 选择命令或技能时继续打开现有能力详情。

## 目标

- 让每个项目在零配置情况下都有可用的落地首页。
- 通过尺寸更大、响应式的 Grid，让 monorepo 中的应用和子包更容易发现。
- 以类似 GitHub 的 Markdown 渲染体验展示仓库文档。
- 展示常用操作，同时不绕过命令预览、信任审阅、参数校验、发布预检或二次确认。
- 允许仓库拥有的 JSONC 元数据调整简介、排序、可见性和快捷操作。
- 保留现有紧凑能力列表，继续承担完整搜索和浏览职责。
- 为可靠的环境状态与运行时状态建立分阶段路线。

## 非目标

- 不用卡片替换中栏能力列表。
- 不允许概览配置任意 shell 命令。
- 首次交付不从概览中立即执行命令。
- 不在未经审阅的情况下推断并写回缺失的仓库元数据。
- 不把推测出的健康状态当成权威环境状态。
- 不在重新进入项目时恢复上次选择的子包或能力。

## 体验模型

### 选择状态

右侧面板存在三种互斥状态：

| 当前选择 | 中栏 | 右侧面板 |
| --- | --- | --- |
| 项目 | 项目的全部能力 | 项目概览 |
| 子包 | 限定为该子包的命令 | 子包概览 |
| 能力 | 保留现有列表上下文 | 现有命令或技能详情 |

进入或切换项目时始终从项目概览开始。在当前会话浏览该项目期间保留子包选择。选择子包会清空已选能力；选择能力时保留其子包范围，以便从详情返回时恢复子包概览。

### 项目概览

项目概览依次展示：

1. 项目标识、简短介绍、信任状态和现有项目工具栏操作。
2. 根据已发现能力推断、并可由项目配置调整的常用操作。
3. 存在本地历史记录时，单独展示“最近使用的子包”。
4. 非根子包的响应式 Grid。
5. 渲染后的根目录 README。

根包已经由项目标题与常用操作表达，不在子包 Grid 中重复展示。

### 子包概览

子包概览包含：

1. 子包名称、路径、简介、类型和命令数量。
2. 子包级常用操作。
3. 简介缺失或明显仍是占位内容时，展示非阻塞的元数据质量提示。
4. 渲染后的子包 README；不存在 README 时展示降级内容。

卡片主体和子包标题负责导航；只有明确的操作按钮才能选择命令。

### 子包卡片

卡片采用中等信息密度：

- 展示名称和项目相对路径。
- 展示简短介绍；发生截断时提供无障碍的展开方式。
- 展示子包分组或类型，以及已发现的命令数量。
- 最多展示两个主要快捷操作；其他操作留在子包概览中。
- 操作始终可见并支持键盘访问，不依赖 hover。

右侧详情区较宽时每行三列，中等宽度时两列，较窄时单列。整个概览只拥有一个纵向滚动容器；README 不得再创建嵌套滚动区。

## 发现、默认值与配置

### 零配置默认值

简介按以下优先级解析：

1. 有效的项目配置覆盖值。
2. `package.json` 中的 `description`。
3. README 中第一个有意义的标题或段落。
4. 仅展示子包名称和项目相对路径。

常用操作根据已发现的命令类别和约定名称推断。推断应当保守地选择一个具有代表性的开发、构建、测试或质量检查操作，且绝不能凭空创建命令。项目配置可以替换标题、调整推断结果的顺序、加入其他已发现能力，或隐藏推断结果。

默认子包排序保持稳定：

1. `apps/`
2. 类似 `play` 的顶层可运行站点或应用
3. `packages/`
4. `docs` 和 `docs/`
5. 其他工作区

同组项目先按本地化显示名称排序，再按项目相对路径排序。最近使用记录永远不会改变该顺序。

### 项目配置

`.craft-hub/project.jsonc` 继续保持可选、声明式、经过 schema 校验并由仓库拥有。实现时应通过可选的概览元数据扩展现有 version 1 schema，而不是引入可执行配置。以下结构仅用于说明：

```jsonc
{
  "version": 1,
  "project": {
    "description": {
      "default": "A local developer workbench."
    },
    "readme": "./README.md",
    "quickActions": [
      "package.json:dev",
      "package.json:test"
    ]
  },
  "packages": {
    "apps/web": {
      "description": {
        "default": "Craft Hub Web workbench."
      },
      "order": 10,
      "featured": true,
      "hidden": false,
      "readme": "./apps/web/README.md",
      "quickActions": [
        "apps/web/package.json:dev"
      ]
    }
  }
}
```

准确字段名仍需经过 schema 评审，但以下约束已经确定：

- 子包键使用规范化后的项目相对目录；`.` 表示根目录。
- README 路径必须是项目相对文件，并且解析结果位于项目根目录内。
- 快捷操作只能通过已有的稳定、带来源限定的选择器引用已发现能力，不能包含命令、argv、工作目录、环境变量值或 shell 片段。
- `order` 是显式数值排序覆盖项。`featured` 只影响视觉突出程度，不会暗中改变能力语义。`hidden` 只从 Grid 中隐藏子包，不会让它退出能力发现或命令搜索。
- 本地化简介继续使用现有 locale map 模型。
- Schema 生成结果、revision、示例、文档和 JSONC 注释保留编辑测试必须同时更新。

### 最近使用的子包

最近使用记录属于机器本地的用户状态。它单独展示，永远不会改变配置排序或默认 Grid 顺序。它不会写入仓库、便携工作区清单或团队同步数据。首版可以在现有本地设置或状态边界中，为每个项目保留一份较短的最近使用列表。

## README 预览

### 发现

项目 README 发现首先检查配置路径，随后检查项目根目录下不区分大小写的常规名称。子包 README 使用相同规则在子包目录中查找。发现结果应明确区分：已找到、不存在、不可读、编码无效、文件过大和路径逃逸；不存在 README 不属于错误。

README 内容需要受限的 runtime/API 契约。Web 客户端不得获得任意文件系统读取能力。请求只能指定已注册项目和可选的已发现子包路径，由 runtime 在项目根目录内解析并校验文件。

### 渲染

预览应当接近 GitHub 仓库 README 的体验，同时继续使用 Craft Hub 的颜色与间距 token。支持标题、段落、列表、任务列表、表格、引用、围栏代码、行内代码、图片和链接。

渲染要求：

- 净化原始 HTML，并拒绝脚本、事件处理器、危险 URL 协议和主动嵌入内容。
- 相对链接和图片以 README 所在目录为基准解析，并确保本地目标仍位于项目根目录内。
- 在桌面或编辑器能力可用时，通过现有安全操作打开仓库文件；经允许的外部 HTTP(S) 链接保持正常浏览器行为。
- 提供无障碍标题结构、表格溢出处理、代码块横向滚动、清晰的链接焦点状态和合理的图片替代文本行为。
- 设置并记录内容大小上限；文件过大或内容为二进制时展示明确的降级状态。
- 按校验后的文件标识和修改时间缓存，并且只让受影响的概览失效。

现有技能源码预览并不是 Markdown 文档渲染器，不应复用它展示 README。

### 文件监听

README 当前不属于能力刷新语义。概览刷新应当增加范围收窄的文档变更 scope，或采用等价的定向失效机制，避免每次 Markdown 修改都重新发现全部能力。只监听已经解析出的根目录和子包 README 候选文件，不需要广泛递归监听所有 Markdown 文件。

## 快捷操作安全

首版中的概览操作只负责选择，不负责执行：

1. 在当前发现快照中解析配置或推断得到的选择器。
2. 在适用时设置子包上下文。
3. 选择对应能力。
4. 展示现有命令详情、最终 invocation 预览、参数和安全 UI。

概览不得直接调用现有运行方法，否则可能绕过未信任项目审阅、参数校验、发布预检、阻塞项、警告或二次确认。选择器缺失或存在歧义时，产生非阻塞项目诊断，并且不提供可执行操作。

后续的一键运行必须先建立一个由能力详情和所有快捷入口共享的统一启动与审阅控制器。只有被分类为低风险、无需参数且没有额外预检的命令才可以进入候选范围，用户仍然必须能够审阅准确的结构化 invocation。

## 架构方向

### Runtime 与 API

- 扩展项目和子包概览数据，但不暴露通用文件系统访问能力。
- 在 runtime 中解析本地化概览元数据，并校验子包与 README 路径。
- 增加专用 README 摘要或内容响应，包含明确诊断和缓存标识。
- 为项目变更事件增加范围较窄的概览或文档刷新 scope。
- 能力发现继续保持只读，并保留 `command` 加 `args`、`shell: false` 和项目工作目录等执行语义。

### Web 工作台

- 将子包选择从 `CapabilityList` 的局部状态提升到工作台 store。
- 明确建模项目、子包和能力三种选择状态，而不是把未选能力统一视为一种空状态。
- 将 `CapabilityList` 中的子包聚合、分组、默认排序和能力计数提取为经过测试的共享 helper。
- 在现有详情面板边界内增加项目概览和子包概览组件。
- 复用项目工具栏操作、UI 按钮、图标、卡片 token、能力风险标签和现有能力详情流程。
- 不改变终端与运行状态的所有权；概览不会创建第二套运行模型。

## 无障碍与交互要求

- 卡片与卡片内部操作拥有不同的焦点目标和无障碍标签。
- 激活卡片永远不会运行命令。
- 每个响应式断点下，Grid 阅读顺序都与视觉顺序一致。
- 选择变化时移动焦点或播报新的面板标题，但不会意外清空中栏搜索。
- 被截断的简介必须向键盘和辅助技术用户提供完整内容。
- 信任、运行、元数据缺失和诊断状态除了颜色外，还必须使用文字或图标语义。
- 加载骨架或选择过渡遵循减少动态效果偏好。

## 首次交付验收标准

- 进入项目且未选择能力时，展示项目概览而不是空状态提示。
- 项目概览列出所有未隐藏的已发现子包，包括没有 scripts 的子包。
- 卡片在单列、双列和三列宽度下均可使用，并能完全通过键盘操作。
- 选择子包时限定中栏并打开其概览；选择能力时打开现有详情。
- 默认子包顺序具有确定性，配置顺序优先，最近使用不会重排 Grid。
- 简介缺失时仍提供可用卡片，并展示非阻塞维护提示。
- 项目和子包 README 存在时正确渲染，不存在时自然降级。
- 不安全 Markdown 无法执行脚本、通过本地路径逃出项目根目录，或触发未经审阅的命令。
- 每个概览快捷操作最终进入与手动选择命令相同的命令详情和确认流程。
- 现有信任、发布、终端、运行历史、能力搜索和紧凑子包列表行为保持不变。

## 测试策略

- Runtime 单元测试覆盖配置校验、选择器解析、默认元数据、路径约束、README 发现、大小限制和诊断。
- Server 测试覆盖概览或 README 响应、语言选择、刷新 scope 和非法项目访问。
- Store 测试覆盖三种选择状态、进入项目时重置、子包范围和仅会话内保留选择。
- 组件测试覆盖卡片导航与操作选择的差异、响应式内容、元数据缺失、README 降级和键盘交互。
- 安全回归 fixture 覆盖原始 HTML、危险协议、逃逸相对路径、SVG 或主动内容，以及存在歧义的快捷操作选择器。
- 现有执行测试继续作为信任、结构化 argv、发布预检、终端流式输出和停止运行的权威保障。

## 风险与缓解措施

- **概览配置演变为第二套命令系统。** 快捷操作只能引用已发现能力，永远不能定义可执行文本。
- **README 渲染扩大内容攻击面。** 使用受限 runtime API、项目根目录约束、内容净化、URL 策略和恶意内容 fixture。
- **详情面板在视觉上过载。** 使用中等密度卡片、限制卡片操作数量、只保留一个滚动容器，并让中栏列表继续承担完整浏览职责。
- **自动操作推断选中了意外命令。** 推断必须确定、保守、可检查并可由配置完全覆盖。
- **子包顺序意外变化。** 使用有文档记录的稳定分组顺序，并将最近使用与 Grid 隔离。
- **状态展示造成错误信心。** 首次交付不包含状态，并要求后续状态具备类型化的 unknown 或 stale 状态及来源信息。
