## Node 按需加载与使用后驻留（2026-10-26）

上一轮的 81.78 MiB 是原生首页出现后两秒的 Node physical footprint，并非稳定存活的 JavaScript 对象。此次先检查已打包 sidecar 的模块加载和 V8 分项，再用真实 Release 界面操作、关窗后的进程计数验证。不强制 GC，不设置更小的 V8 堆上限。

### 82 MiB 的来源与改动边界

隔离资料、相同 Node 24.18.0、启动 2.5 秒时的 inspector 诊断如下。它会改变进程开销，仅用于定位；不能与未插桩 footprint 相加或互换。

| V8 / Node 诊断，MiB | 同样插桩的空 Node | 优化前 sidecar | 优化后 sidecar |
| --- | ---: | ---: | ---: |
| JavaScript heapUsed | 4.97 | 24.51 | 20.03 |
| JavaScript heapTotal | 7.27 | 57.20 | 39.36 |
| external | 2.03 | 7.58 | 6.89 |
| 代码与字节码及元数据 | 0.62 | 3.07 | 2.89 |

`heapUsed` 是 `heapTotal` 的一部分，代码等也与堆分项重叠；external 包含 ArrayBuffer，不能重复相加。footprint 还包含 Node/V8 原生运行时、栈、加载器和库等成本，以上不是 82 MiB 的互斥账单。采样堆栈的主要大项包含 ESM 编译、源码解码及共享依赖的初始化。诊断显示减少的是实际加载的依赖和启动分配，而不是发现了一个 82 MiB 的业务缓存。

原版即使未启用 To Do，仍加载约 1.9 MB 的 MCP 相关共享 chunk、PTY 和 Windows 命令解析依赖。共享 chunk 同时包含公共依赖，不能全归给一个 SDK。优化后启动模块记录不再出现 MCP client/stdio、PTY 和 Codex SDK；必需的 schema、配置解析、文件观察等公共依赖仍保留。`profile-before/`、`profile-after/`、`profile-bare/` 保存模块清单、V8 统计和采样 heapprofile，`cleanup.json` 均确认进程退出。后端诊断产物与最终包的后端文件逐一 SHA-256 相同。

已完成的边界调整：

- 未启用的内置 To Do 插件仅保留状态元数据，启用后才导入实现、创建传输对象；MCP SDK 到首次允许的连接器调用才导入。禁止的工具及未确认写入不会触发加载。
- PTY 到可信项目的首次命令执行才导入；异步加载后重新检查工作目录及执行守卫。Windows 的 `cross-spawn` 解析到实际需要时才加载。
- Codex SDK 到首次 AI 生成或代理任务才导入；MCP server 到真正启动 MCP 服务、完成宿主检查后才导入。
- 主窗口全部关闭时跳过原生首页每分钟的来源数据刷新，避免仅为隐藏界面持续调用外部连接器。后台任务、事件订阅、通知及必要观察继续运行；一分钟的轻量定时检查仍存在。

### 关窗后的采样口径

基线为前一轮 WKWebView 优化完成后的 `lazy-webview-20261026/after-final/Craft Hub Prototype.app`，本轮为 `node-residency-20261026/after-final/Craft Hub Prototype.app`。主程序 SHA-256 分别为 `c844deb824a6c6937516621e8b5daf86ec4b67aa9f71b2b6fa496b95b0475b41` 和 `db784417fdb1a10859d947caaff2498aeb94cbb9ab3ed2b14a1e23a3939cd32a`；网页的 587 个文件逐一相同，记录在 `artifact-comparison.json`。每次复制为独立 bundle 身份并使用独立 HOME、Foundation HOME、运行时和网页资料。真实 UI 顺序为项目、软件中心、开发环境、插件管理、首页，再打开完整网页工作台；确认网页就绪后关闭主窗口，保留 App、sidecar 和网页会话驻留。没有登记项目、连接真实云/账号、运行命令或 AI 任务。

## 复现

先构建当前原生包和相同源码的 Electron arm64 包，再执行：

```sh
pnpm build:macos
pnpm -C apps/desktop build
CRAFT_HUB_DESKTOP_OUTPUT_DIR=apps/macos/build/electron-baseline node --import tsx --input-type=module -e 'import { packageMacos } from "./scripts/package-macos.ts"; await packageMacos({ architectures: ["arm64"], createArtifacts: false, adHoc: true, codexMode: "external" })'
pnpm benchmark:macos --electron 'apps/macos/build/electron-baseline/Craft Hub-darwin-arm64/Craft Hub.app' --iterations 3 --output apps/macos/build/performance-new-run
```

每次选择新的 `--output` 目录；存在 `report.json` 时脚本拒绝覆盖。输出包含 report、逐次 trace 和原始 footprint，记录源码 revision/dirty、原始产物签名、Node、机器、就绪标记、进程归属、采样完整性与清理结果。迭代失败也保留已有结果；`completed` 只表示启动迭代完成，仍须检查各次 `memory.complete` 和 cleanup。文件位于忽略的构建目录，不提交机器路径与状态。脚本只清理本次独立副本中身份仍匹配的进程，保留未退出进程的临时资料，不按进程名结束其他应用，也不直接强制终止 Apple XPC 服务。

原生 `Performance` 日志类别提供固定事件名的 Logger/signpost；`./script/build_and_run.sh --telemetry` 可观察。`CRAFT_HUB_PERFORMANCE_TRACE` 指定绝对路径时额外写本机 JSON，不包含 token、项目内容或探测输出。`CRAFT_HUB_NATIVE_DATA_DIR` 隔离运行时、草稿和偏好；Electron 对照使用 `CRAFT_HUB_DATA_DIR` 加 `CRAFT_HUB_DESKTOP_PROFILE_DIR`。这些是开发验收入口，不是数据迁移操作。
