# ADR 0013: Share business pages across desktop hosts

Update, 2026-11-04: [ADR 0014](0014-keep-electron-and-use-an-optional-resident-companion.md) supersedes the independent macOS host and remaining-page convergence queue. Shared Vue business pages remain the direction; optional native resident entry points now reuse Augma. The following records the preceding decision.

Date: 2026-11-04. Status: accepted. This supersedes the incremental business-page rewrite in ADR 0012; profile isolation, runtime ownership and release acceptance requirements remain in force.

Vue is the single implementation of business pages for the browser, Electron and the macOS WKWebView host. Maintaining parallel SwiftUI pages has duplicated presentation state, wire models and verification while plugin pages already depend on the shared Web renderer. The macOS host keeps native window chrome, menus, shortcuts, quick-capture entry points, secure storage, isolated account sign-in, file dialogs, updates and sidecar lifecycle. Electron remains the cross-platform host. New business features belong in the shared Web UI; native additions require an operating-system capability or a measured interaction benefit.

Apple-style presentation comes from shared controls, system fonts, semantic colors, consistent spacing, grouped surfaces and keyboard/focus behavior. macOS supplies live system colors and accent preferences through the existing appearance adapter; browser rendering keeps its own complete fallback. The host does not maintain a second business design system or provider-specific screen.

Convergence proceeds by complete workflow groups. The first group is environment inspection, setup profiles, source connections and configuration review: native sidebar and command-palette entries open the shared scoped Web routes. `/environment/sources` exposes source connections independently of profile preparation, reusing the same form and declared provider capabilities. Duplicate Swift pages, stores and their unused wire models are removed together; runtime/provider validation and behavior remain shared. Environment writes join the existing pending-operation report before submission, protecting browser/native navigation and host termination while their requests settle. Existing projects, tools, software, plugin-management and diagnostic pages remain native until their corresponding groups are accepted; this decision does not claim their migration is complete.

Each group requires shared-page regression checks and a packaged macOS review before replacing the daily-use app. Keep user profiles, credentials, backups and drafts intact. A renderer change neither merges Electron/native profiles nor completes distribution, minimum-system or long-term daily-use acceptance.

The [remaining-page inventory and convergence order](../plans/macos-shared-ui-convergence.md) specifies tools/navigation and common settings, diagnostics/plugin management, software, home/work items/capture, projects/commands/terminal, then palette and host cleanup. Native panel containers remain; their business contents converge on Vue. Bootstrap/recovery, isolated sign-in, system permissions and the existing trusted local approval of personal-cloud commands remain native. SwiftTerm stays as a migration fallback until the shared terminal passes real interaction acceptance; retaining it longer requires a separately documented exception. Accept each workflow group before removing its duplicate Swift implementation, then verify the final artifact again.
