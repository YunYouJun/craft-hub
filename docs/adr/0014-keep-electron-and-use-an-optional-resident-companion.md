# ADR 0014: Keep Electron and use an optional resident companion

Update, 2026-11-04: [ADR 0015](0015-use-an-on-demand-shared-runtime-for-cloud-capture.md) accepts on-demand shared execution so cloud capture can work while Electron is fully quit. The primary-host/product split here remains; the following snapshot-only lifecycle describes the implemented first version, not the final cloud-capture target.

Date: 2026-11-04. Status: accepted by the maintainer. Electron remains the primary desktop host and Vue owns the business pages. This supersedes the independent macOS primary-host direction in ADR 0012 and the macOS host/page convergence queue in ADR 0013. Preserve the existing native candidate, profiles, credentials, drafts and acceptance evidence; no profile or public-link migration is implied.

Use Augma's existing native menu bar and durable quick-capture flow as the first resident companion instead of shipping a second menu-bar application. Craft Hub supplies an explicitly shared, dated, bounded Today summary and remains responsible for business rules, accounts, trust and execution. Augma stays running and saves its own drafts when Electron fully quits. Opening the full workbench targets Electron; complex business pages stay there. Augma is optional and Craft Hub remains independently usable.

The first version uses a user-selected local JSON export, updated only when Today is requested or the user explicitly shares again. It introduces no background Node process, account-token sharing, widened Agent grant or shared profile writer. Cached data shows its update time and source coverage. Preserve existing native drafts rather than silently importing or merging them. A live companion would need one shared runtime owner, explicit lifecycle/authentication contracts and separate acceptance. The current Augma checkout targets macOS 26, so this integration does not establish macOS 15 support. See [the companion guide](../guide/resident-companion.md).
